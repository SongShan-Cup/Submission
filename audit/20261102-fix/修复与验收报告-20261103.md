## 修复与原因

### 1. 缺失的海光 MHA 后端与注意力显存开销

原环境关闭 FlashAttention，海光 MHA 未注册。重新以 ATen、CCL、FlashAttention 和 gfx936 编译 InfiniCore，补齐当前厂商 wheel 的链接与符号加载兼容性。

海光 MHA 改用厂商 varlen FlashAttention，避免构造完整 `[B,H,S,S]` 矩阵；支持批次、GQA、因果注意力与非连续输出。未注册后端时改为抛出明确错误，避免空函数指针崩溃。动态加载优先使用实际的 `FA_SO_PATH`，兼容当前 Python 3.11 wheel。

实际发现厂商内核对 72/96 维注意力需要填充到 128，同时保留原始 softmax scale；Q/K/V 共用起始地址时结果也会出错，增加独立缓冲兼容。H3 实际 head_dim 为 128；Qwen 视觉编码器为 72。96 为额外兼容验证，不应误称为 H3 的 head_dim。

参照路径显式使用可用的 FlashAttention，避免 Diffusers 检测门槛触发稠密 SDPA 回退。这些修改解决了本例 768p 配置的运行阻塞和注意力矩阵显存爆炸；未进行 2K 配置的显存验收。

### 2. 导致成片纹理失真的输出同步遗漏

`InfiniLM/csrc/engine/rank_worker.cpp` 中的 `skip_sampling` 路径曾在工作流完成前设置 `job_done_`，上层会在另一条流中拷贝尚未完成的结果。该路径用于 H3 与条件编码器。

现在先同步当前 rank 的 GPU 工作流再发布输出；Python bridge 也在原生线程使用输入前同步 Torch 预处理流，涵盖新生成的旋转位置缓存。

同一首步输入调用两后端，视频相对 RMSE 从修复前 **71.34%** 降至 **2.44%**；音频输出为 **2.82%**。最终余弦相似度分别为 0.99970、0.99960。完整视频抽帧也显示纹理异常明显消失。这是本次定位到的主要额外画质故障。

### 3. AdaLN 标量加法形状约束

原生 Add 要求等形状，`1 + scale` 的标量调用会失败。使用零步长视图将常数 1 扩展到 scale 的形状，保留参考计算顺序 `x * (1 + scale) + shift`，避免分配完整全 1 张量。同时为 Add 异常补充形状信息。

### 4. 生成参数与 VAE 精度

此前成功视频多为 576×384、2 或 10 步，另有缩小版本。此次按说明使用 50 步与默认 768 短边，未使用这些低步数样例作为最终质量结论。

视频、音频 VAE 不再被强制转换到 BF16，而是保留加载器要求的 FP32。检查到视频 VAE 的 703 个参数张量、音频 VAE 的 832 个参数张量均为 FP32。本次未单独消融 VAE dtype 对画质的贡献，因此不把画质改善全部归因于该项。

### 5. 参照路径库加载

原参照运行已生成完整视频，但在退出时出现过段错误。示例现按需导入原生模块，PyTorch 参照路径不加载 InfiniCore 的 HIP 库。修改后的参照逐层采集与首步回放已正常完成，未复现该退出异常。

## 尚未完全对齐的范围

Qwen 条件编码仍有局部数值差异：真实含图输入的逐 token 相对 RMSE 中位数约 3%，全局 RMSE 约 70%，误差平方和约 99.9% 由 10 个图像 token 贡献，其中两个位置占绝大部分。纯文本分项全局相对 RMSE 约 0.407%，余弦相似度约 0.9999996。证据见 `condition-comparison.json`、`condition-token-errors.json`。

因此，目前定位到的剩余精度重点是视觉分支的少数异常 token；不能宣称所有内部状态已完全对齐，也不能据本次单例推断所有语义条件都没有影响。旧逐层调试中的 float32 全向量 cosine 曾因归约精度出现大于 1 的无效统计，不用于验收结论；正式首步及条件对照已使用 float64 统计。

本轮验收任务为 FL2VA。Ref2VA、多帧参考、首尾帧组合、2K 增强以及音频听感未完成专项验收。已有本地基础模型的 768p 结果不等同于已部署官方 2K 增强流程。
