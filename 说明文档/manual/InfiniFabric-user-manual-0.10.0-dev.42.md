# InfiniFabric 管理员与用户操作手册

对应版本：0.10.0-dev.42。更新日期：2026-10-29。

本版补充项目大小检查、文件保存校验、AFS 上传续传和回收站操作说明。整节点八卡训练与共享编译见第 35 节，所用节点须已完成相应认证。

网站入口为 https://tools.infinitensor.com/compute/scheduler/ 。节点暂停、排空或账号没有资源权限时，开发入口不可用，请联系管理员检查。

菜单或按钮与手册不同，请让管理员核对网站版本。先按第 0 节选择路线，再按章节操作。离线包附有可直接上传的示例文件和试用记录表；不需要从截图抄代码。

## 0. 第一次试用怎么走

### 0.1 先选使用方式

| 你的目的 | 从哪里开始 | 是否占用 DCU | 本手册步骤 |
|---|---|---|---|
| 上传、编写、保存代码 | 我的项目 | 否 | 7、13 |
| 在共享终端编译，再排队运行 | 我的项目 → 登录工作区 → 批作业 | 编译不占卡，程序获配后独占八卡 | 31、32 |
| 在 Bash 中调试 DCU 程序 | 我的项目 → Bash 终端 | 独占整节点全部卡 | 8 |
| 一格一格运行 Python，保留变量 | 我的项目 → 交互开发 | 独占整节点全部卡 | 9 |
| 不需要编译，直接排队跑 Python 或 Bash | 我的项目 → 批处理作业，或批作业 | 独占整节点全部卡 | 10、31.4 |
| 查看历史日志、下载结果 | 批作业 → 日志与结果，或开发实例 → 对应记录 | 读取已保存结果不需要重新申请卡 | 12、31.4 |
| 试基础资源分配和 CPU 文件操作 | 资源申请 | 可能预留卡，但不开放任意 DCU 程序 | 14 |

**建议第一次选择“共享编译 → 批作业”。** 完成后再试独占 Bash 和交互开发。不要先在“资源申请”领取两张卡，再期待它变成可运行任意 DCU 程序的终端。

### 0.2 节点分工示例

| 节点 | 用途 | 你应看到的结果 |
|---|---|---|
| scnet-2 | 共享 CPU 登录工作区 | 每人一个工作区，节点最多八个；不分配 DCU，排空时不可新建工作区 |

## 1. 使用前先看这几项

1. 普通用户需要账号审批、远程运行权限、资源池授权和足够的额度。注册成功不等于资源已经开通。
2. 自定义 DCU 程序目前使用独占节点。领取部分卡的基础资源申请只能使用 CPU 终端、文件和固定检查任务，不能运行任意 DCU 代码。
3. 当前整节点组件已通过八卡模型并行、八进程 DDP 和每进程两个 DataLoader worker 的节点测试。网站按账号权限和节点状态开放对应环境，用法见第 35 节。
4. 关闭网页不停止程序，也不暂停使用期限。结束时点击“停止并释放资源”，等待回收确认。
5. 项目文件和实例文件分别保存。实例内修改不会自动同步回项目。
6. 示例不需要下载模型或联网安装软件。请先完成示例，再提交自己的项目。
7. 实例文件通过网页传输时，单文件最多 128 MiB；结束自动保存的总量最多 128 MiB、256 项。超过保存总量可以提前分批下载，更大的单文件需要先配置持久存储。

本手册提供完整操作步骤，不表示所有服务器都已安装全部后端。灰色按钮、空环境列表和“待核对”需要按提示处理，不能通过增加额度或修改脚本绕过。

## 3. 管理员：确认资源已经接入

1. 系统管理员登录，打开“资源池与节点”。
2. “资源连接”应至少有一个资源池。“分配开关”应已启用，它来自部署配置，网页不代替首次安装。
3. 正常试用时，“维护状态”应未开启维护模式。
4. 点击该池的“刷新节点检测记录”。
5. 记录资源池、节点名称、每节点卡数、可分配卡数和终端状态。
6. 确认试用资源没有需要保护的外部任务，不能把低利用率当作空闲证明。

**通过条件：** 池存在，节点可达且执行就绪，所需开发方式有可用环境。CPU Bash 就绪不等于 DCU 已验证。

池为空、分配未启用或节点身份变化时，由接入管理员在服务器上处理凭据、主机身份和执行组件。网页不填写 SSH 私钥、sudo 密码，也不安装节点软件。处理后重新检查。

SCNet 云资源与传统 SSH 节点是不同入口。四台机器是否接入，要看池中的实际列表，不能只看“服务器概览”的登记记录。

## 4. 管理员与用户：准备两个试用账号

建议用 `trial-a`、`trial-b`；名称已存在就换名。不要修改业务用户来做撤权和到期测试。

### 4.1 用户注册

1. 登录页展开“注册新账号”。
2. 填写用户名、显示名称、密码和确认密码。密码为 12–128 个字符。
3. 点击“提交注册申请”，把用户名告诉管理员，等待审批，不发送密码。
4. 为第二个账号重复操作。

### 4.2 管理员开通

1. “用户与权限” → “用户算力开通”，找到 `trial-a`。
2. 点击“开通或调整算力”，选择试用池。
3. 按下表填写。示例针对一台八卡节点，其他节点按实际卡数调整。
4. 点击“保存设置”，等待审批、额度和池授权各步完成。
5. 中途失败时，刷新并核对已保存设置，再重试；不需要重建用户。
6. 对 `trial-b` 重复操作。

| 字段 | 八卡试用示例 | 含义 |
|---|---|---|
| 排队上限 | 4 | 等待中的申请数 |
| 并发申请上限 | 1 | 同时占用一份资源 |
| 加速卡并发上限 | 8 | 独占八卡必须覆盖全部八张卡 |
| 单次最长时间（分钟） | 10 | 每次申请时长上限 |
| 24 小时卡时额度 | 8 | 多次短试用的额度，计算见第 15 节 |
| 24 小时节点时长（小时） | 2 | 节点执行时长额度 |
| 最高优先级 | 50 | 不为试用抬高到业务任务之上 |

只修改专用试用账号。池和节点执行器可能有更低上限。

### 4.3 用户检查

1. 用单独的浏览器窗口或浏览器配置登录 `trial-a`。标签页可能共享会话，先确认右上角用户名。
2. “用量与额度”核对卡数、时长。
3. “开发实例”查看三种方式的状态。
4. “我的项目”选择方式，检查运行环境列表。

**通过条件：** 普通用户角色、额度和环境正确。三种方式全禁用时读取原因，不重新注册或重复分配卡。

## 5. 管理员：账号、角色与密码

### 5.1 审批、停用和角色

1. “用户与权限”展开“高级：平台角色与服务器身份策略”。
2. 找到用户，检查“平台角色”“资源等级”“账号状态”“远程运行权限”。
3. 新用户点击“保存审批结果”，已有用户点击“保存用户策略”。
4. 让用户重新登录或刷新权限。

不能停用或降级最后一名有效管理员，不用唯一管理员做降级试验。停用会使会话失效并触发相应任务处理，但节点失联时仍需等待回收。账号停用不证明所有进程已退出。

### 5.2 重置密码

1. 找到已启用用户，点击“签发密码重置码”。
2. 通过可信渠道交付一次性重置码。有效期 15 分钟，刷新后不再显示。
3. 用户在登录页“重置密码”填写用户名、重置码和新密码。
4. 用新密码登录。原会话和旧凭据按重置规则失效。

不把重置码放进试用记录、截图和公开工单。

### 5.3 管理员首次登录

首次设置或账号恢复才使用“管理员令牌登录”。输入现场取得的有效令牌，进入“我的账号”设置密码，之后用账号密码登录。过期令牌需要服务器端恢复，普通用户不使用管理员令牌。

## 6. 管理员：资源池与节点策略

### 6.1 默认时长和上限

1. “资源池与节点”展开试用池的“默认时长与申请上限”。
2. 专用池可设默认 5 分钟、最长 10 分钟，每次最多卡数不超过 8。
3. 只有需要多节点基础申请且容量足够时，才调整“每次最多节点”。
4. 点击“保存默认值与上限”，确认表单下方显示“已保存”及四个数值，再整页刷新核对。

输入后但尚未保存时，表单会显示“有未保存的修改”。默认时长不能超过最长时长，最长时长不能超过页面标注的节点上限。保存失败时保留输入；提示“未保存”表示旧策略继续生效。修改策略需要管理员权限。

只影响新申请，不修改已有截止时间。可申请时长还受用户和执行器上限限制。

### 6.2 暂停、排空、恢复

| 按钮 | 效果 | 已有任务 |
|---|---|---|
| 暂停分配 | 不再接收新分配 | 按原期限运行 |
| 排空节点 | 停止新分配并等待占用归零 | 不主动杀任务 |
| 恢复分配 | 重新接受分配 | 需要新鲜且身份一致的检测结果 |

只操作专用节点，阅读确认框再“确认操作”。恢复禁用时先刷新检测；身份变化需重新核验接入。

### 6.3 维护模式

“进入维护，暂停新申请”只暂停新申请，已有实例继续运行。“退出维护，恢复新申请”恢复接单。维护不是停止网站，也不代替升级前排空和备份。

## 7. 普通用户：创建项目和准备示例

随手册的示例包包含 `cpu_check.py`、`gpu_quickstart.py`、`settings.json` 和 NumPy 示例。没有包时可复制第 30 节代码。

1. `trial-a` 登录，打开“我的项目”。
2. 输入 `manual-trial`，点击“新建项目”。
3. “新文件路径”填 `cpu_check.py`，点击“新建文本文件”。
4. 粘贴第 30 节 CPU 代码，点击“保存文件”，等待“已保存 v…”提示。
5. 同样准备 GPU 示例和配置，或通过“上传文件”选择多个文件，在“上传队列”核对后点击“开始 / 继续上传”。
6. 使用“编辑”“下载”核对内容，刷新后检查保存结果。

`settings.json`：

```json
{"lr": 0.02}
```

用项目相对路径，如 `train.py` 或 `src/model.py`，不填 `/home/...`、`../...`。同名上传会列出当前版本，勾选确认后保存为新版本；旧运行继续使用提交时的代码。小文本也可通过编辑器保存。

**通过条件：** 三个文件可查看、下载且刷新后存在。保存项目不占卡，离开页面前仍需手动保存。

## 8. 普通用户：独占 Bash、训练和推理

终端结束后，本页保留最后的输出，输入区变为只读。刷新页面或切换账号、节点、资源后不保留这段显示；需要长期保存的结果应写入文件，并在“文件”页确认保存版本后下载。保留输出不会继续占用节点，也不会允许在已结束的终端发送命令。

### 8.1 创建终端

1. 项目“启动项目”选择入口 `gpu_quickstart.py`。
2. 使用方式“Bash 终端”，参数留空。
3. 选显示 Python、PyTorch 版本的可用环境，时长 5 分钟。
4. 点击“下一步：检查资源”，核对节点数、整机卡数和预计卡时。八卡 5 分钟约 0.67 卡时。
5. “确认并启动”，等待“运行中”和项目文件已准备。
6. “打开终端” → “连接终端”。

Bash 已进入项目运行目录，不自动运行入口文件。

### 8.2 文件与 CPU

```bash
pwd
ls
python3 -u cpu_check.py
```

预期 `CPU_OK 10416`，生成 `cpu_result.json`。这不证明 DCU 可用。

### 8.3 DCU 检查

```bash
python3 -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.device_count()); print(torch.cuda.get_device_name(0))"
```

DCU PyTorch 使用 `torch.cuda` 接口。预期可用性为 `True`，有设备名称。可见卡数不代表多卡训练通过。为 `False` 或报错时，保存错误和实例 ID，联系管理员；不通过可见卡环境变量代替权限隔离。

### 8.4 训练、恢复、推理

```bash
python3 -u gpu_quickstart.py --steps 12
python3 -u gpu_quickstart.py --steps 16 --resume checkpoint.pt
python3 -u gpu_quickstart.py --infer --resume checkpoint.pt
ls -l checkpoint.pt predictions.json
```

默认只使用 `cuda:0`。每步输出 `step`、`loss`、`lr`，保存 `checkpoint.pt`；推理输出 `mode` 为 `inference` 并保存 `predictions.json`。恢复的 `--steps` 是累计步数，不是新增步数。

**通过条件：** 三次执行均返回命令提示符，结果存在且可下载。不同环境不要求 loss 逐位相同。


示例逐步读取配置，所以可在运行中生效。改 Python 源码通常要重新运行，网页保存不自动热重载。

## 15. 额度怎么计算

| 额度 | 限制 |
|---|---|
| 排队上限 | 等待的申请数 |
| 并发申请上限 | 同时使用的申请或任务数 |
| 加速卡并发上限 | 同时占用的卡，独占按整机卡数 |
| 单次最长时间 | 每次申请时长 |
| 24 小时卡时额度 | 交互实例按申请时长；新批作业按程序结算时长 |
| 24 小时节点时长 | 节点执行时长 |

八卡节点 5 分钟：8 × 5 ÷ 60，约 0.67 卡时。只用 `cuda:0` 也占八卡并发。

交互实例和历史固定任务按申请的最长时间计入额度，提前停止不按实际用时退回。**从 dev.24 起的新批作业先预留最长时长，程序结束并确认清理后按实际程序秒数结算，详细规则见第 31 节。** 未执行即取消不计执行消耗；未确认回收或未取得计时回执时继续保留预留额度。使用最近 24 小时窗口，不是零点清零，不是费用账单。

管理员在“用量与额度”调整并“保存额度”。项目存储额度在“我的项目”底部，和计算额度不同。有额度仍排队时检查节点、旧申请、环境、维护和排空；提高额度不能解决环境未验证。

2. “更多管理工具” → “CPU 隔离终端”，在“数据资源授权”授权登记的工作区与只读数据集。
3. 表单选择节点、工作区、数据集和时长，点击“打开隔离终端”。
4. `pwd`、`ls` 检查自己的目录，在私有区写 `note.txt`，读取授权数据集。
5. 数据集只读，不修改权限尝试写入；未授权资源不应可选。
6. “关闭并回收”，等待关闭。持久区重连后文件应在，临时目录不保留。
7. 回收后可“提交工作区验证作业”，观察写入与校验。

此终端没有加速卡和网络，空闲 5 分钟回收、失联宽限 20 秒，时长还受页面和后端限制。普通用户日常从“开发实例”使用资源，不把该工具当作 DCU Bash。

## 20. 服务器维护终端

前提：已有可信 SSH 账号入口、主机密钥和 Shell 授权。初始令牌会话不能直接使用，需要设置密码后正常登录。

1. “更多管理工具” → “服务器维护终端”。
2. 系统管理员可在“批量服务器账号授权”选择平台用户、动作和账号入口，点击“提交整批授权”。
3. 在“服务器与 Linux 账号”选择目标，点击“连接 Shell”。
4. 首次只运行 `id`、`pwd`，确认服务器与身份。
5. 逐条发送时可展开“发送命令”，填写后点击“发送”。
6. 完成后“断开”，核对会话记录。

维护终端使用 Linux 账号原有权限，不提供普通作业隔离；断开后后台进程可能继续运行。15 分钟无输入或连接满 1 小时自动断开，不支持 root、SSH 转发和 setuid。

批量授权只绑定已有账号，不创建系统用户。此入口不用于让普通用户绕开资源申请，也不执行本手册外的系统修改。

## 24. 固定作业流

前提：传统执行通道已配置，提交者对源和目标节点有授权。只有 SCNet 池时，可能没有此类服务器可选。

## 25. 外部任务、审计和恢复

### 25.1 外部任务

“外部任务观察”显示未由平台启动的进程及占用。归属不明的显存不视为空闲，也不因此取得杀进程权限。试用只查看和记录，不终止别人 PID、容器和服务。

### 25.2 审计

“审计记录”按时间查看授权、额度、作业和回收事件，核对操作者与对象。不要求终端命令、密码和文件内容出现在审计里。

### 25.3 异常恢复

1. “资源池与节点” → “云资源恢复与回收”，查看未知申请、终端保存错误和设备锁。
2. 记录申请 ID、所有者、节点和错误。
3. “重新核对”只查询和对账，不重新运行程序。
4. 要结束自己的测试申请，使用“取消并回收”或“请求回收”。
5. 节点不可达时保留未知和占用，等恢复或运维处理，不强制标空闲。

网页没有完整的控制面备份、恢复和升级入口。这些仍按服务器维护流程执行，不用重置数据库、删目录或重启全部服务代替。

## 26. 高权限操作模拟

“更多管理工具” → “高权限操作策略”显示禁止项、现场维护项和模拟计划，不在真实服务器创建账号。

1. 在无活动资源且满足条件的专用节点选择测试账号计划。
2. 测试名 `iflab_demo`，模拟 UID/GID 均为 `60001`。
3. “生成模拟计划”，展开内容核对对象、摘要和前提。
4. “复核上述计划（不授权真实执行）”。
5. “运行内存模拟”，检查模拟结果。

计划 15 分钟过期，节点变化或占用可导致复核失败。60000–60999 只是演练参数范围，不表示实际 UID 空闲。完成后不应出现真实系统用户。

## 27. 常见问题

| 现象 | 检查与处理 |
|---|---|
| 资源池为空 | 管理员检查接入和用户授权；用户不用填写 SSH 地址 |
| 环境为空 | 检查所选方式、节点和软件，刷新环境 |
| 三种方式禁用 | 查看角色、远程运行、池授权、环境和额度的具体原因 |
| 八卡申请失败 | 卡并发至少 8，时长额度够覆盖整节点 |
| 有额度仍排队 | 检查旧申请、整节点空闲、维护和排空 |
| 终端没 DCU | 是否创建了基础 CPU 申请；从项目新建 DCU 实例 |
| 改码无效 | 确认改的是运行目录，程序是否重新加载 |
| 文件冲突 | 下载草稿，比较版本，合并或另存为 |
| 终端无响应 | 检查焦点、期限和连接，适应窗口或 Ctrl+L，再核对重连 |
| 会话结束 | 重新登录找原实例，不重复申请 |
| 程序退出卡未释放 | 等回收确认，不手改资源记录 |
| 保存失败 | 检查大小、条目、空间，在保留期内下载并重试 |
| 卡时没退回 | 按第 15 节检查申请最长时长规则 |
| 多卡、DataLoader、子进程失败 | 确认使用已认证的整节点环境；仍有异常时，提供命令、实例 ID 和日志 |
| 日志重复或不完整 | 已知日志问题，保留已有日志与最小例子交管理员 |

反馈提供用户名、实例名称和 ID、时间、步骤及无敏感信息的错误。不发密码、令牌、私钥或别人文件。

### 30.2 gpu_quickstart.py

默认一张卡，DataLoader 使用 `num_workers=0`。添加 `--device cpu` 可验证 CPU PyTorch，但不算 DCU 通过，且已申请的卡和时长照常计入额度。

```python
"""Small ordinary PyTorch train/infer project; no downloads or platform API.

python3 gpu_quickstart.py --steps 12
python3 gpu_quickstart.py --steps 16 --resume checkpoint.pt
python3 gpu_quickstart.py --infer --resume checkpoint.pt

An optional settings.json containing {"lr": 0.02} is reread between steps.
Changing Python source takes effect when the program is restarted.
"""
import argparse
import json
from pathlib import Path
import time


def main():
    import torch
    from torch.utils.data import DataLoader, TensorDataset

    p = argparse.ArgumentParser(description=__doc__)
    p.add_argument('--steps', type=int, default=12)
    p.add_argument('--resume')
    p.add_argument('--infer', action='store_true')
    p.add_argument('--delay', type=float, default=0)
    p.add_argument('--device', default='cuda:0')
    a = p.parse_args()
    if not 1 <= a.steps <= 10000 or not 0 <= a.delay <= 10:
        p.error('steps must be 1..10000 and delay 0..10 seconds')
    torch.set_num_threads(2)
    torch.manual_seed(17)
    if a.device.startswith('cuda') and not torch.cuda.is_available():
        raise RuntimeError('No GPU: open a certified GPU development instance first')
    model = torch.nn.Sequential(torch.nn.Linear(4, 16), torch.nn.ReLU(), torch.nn.Linear(16, 2)).to(a.device)
    optimizer = torch.optim.Adam(model.parameters(), lr=0.02)
    first = 0
    if a.resume:
        saved = torch.load(a.resume, map_location=a.device, weights_only=True)
        model.load_state_dict(saved['model'])
        optimizer.load_state_dict(saved['optimizer'])
        first = saved['step']
    x = torch.linspace(-1, 1, 128).reshape(32, 4)
    y = torch.stack((x.sum(1), x[:, 0] - x[:, 3]), dim=1)
    if a.infer:
        model.eval()
        with torch.no_grad():
            result = model(x[:2].to(a.device)).cpu().tolist()
        Path('predictions.json').write_text(json.dumps(result), encoding='utf-8')
        print(json.dumps(dict(mode='inference', restored_step=first, output='predictions.json', values=result)), flush=True)
        return
    # num_workers=0 is deliberate: this sample works within the current small
    # process budget and does not imply multi-process GPU/DDP certification.
    loader = DataLoader(TensorDataset(x, y), batch_size=8, shuffle=False, num_workers=0)
    for step in range(first, a.steps):
        settings = Path('settings.json')
        if settings.exists():
            lr = float(json.loads(settings.read_text(encoding='utf-8'))['lr'])
            if not 0 < lr <= 1:
                raise ValueError('settings.json lr must be in (0, 1]')
            for group in optimizer.param_groups:
                group['lr'] = lr
        losses = []
        for inputs, target in loader:
            optimizer.zero_grad(set_to_none=True)
            loss = (model(inputs.to(a.device)) - target.to(a.device)).square().mean()
            loss.backward()
            optimizer.step()
            losses.append(float(loss.detach().cpu()))
        torch.save(dict(step=step + 1, model=model.state_dict(), optimizer=optimizer.state_dict()), 'checkpoint.pt')
        print(json.dumps(dict(step=step + 1, loss=sum(losses) / len(losses), lr=optimizer.param_groups[0]['lr'], checkpoint='checkpoint.pt')), flush=True)
        time.sleep(a.delay)
    print(json.dumps(dict(mode='training', device=a.device, checkpoint_bytes=Path('checkpoint.pt').stat().st_size)), flush=True)


if __name__ == '__main__':
    main()
```

## 31. 共享登录工作区与整节点批队列

### 31.1 适用范围和管理员准备

此功能参考 Slurm 的准备、提交、排队和执行流程，使用平台自己的队列；没有安装 Slurm，也不提供 `sbatch`、`srun`、`sacct` 的完整兼容接口。首版一个批作业独占一个计算节点及其全部卡，不支持多节点并行作业。队列不承诺预约开始时间。

管理员需先安装分别通过认证的登录组件和计算组件。登录节点角色由受保护配置指定，不依赖节点编号。指定为登录节点后，该候选组件不再把此节点用于 GPU 作业。选择一台空闲 SCNet 节点作为内部试点登录节点即可；以后可迁往专用 CPU 节点或虚拟机，不应长期为编译闲置八张卡。该安装步骤不能仅由网页中的“恢复分配”代替。

1. 在“用户与权限”审批两个普通账号，开启远程运行权限。

4. 用户打开“登录工作区”应看到节点选项；打开“批作业”应看到通过程序计时认证的计算环境。空菜单表示尚缺连接、认证或授权，不能用环境变量替代。

共享登录工作区只面向可信内部用户。当前 SCNet 无可写 cgroup，使用独立 UID、私有命名空间、文件访问规则、系统调用限制和进程监控。dev.33不再设置两核限制，继承节点 CPU 可用范围；每人一个工作区、每节点最多八个工作区。每工作区数据段和聚合 RSS 保护值为 16 GiB，地址空间 64 GiB，最多 512 个线程，不再施加 CPU 秒数限制。监控存在采样间隔，不是 cgroup 的硬内存保证；启动需至少 24 GiB 当前可用内存。这些属于共享登录保护，不用于整机计算。未升级节点仍使用旧策略。

管理员可在“资源池与节点”的恢复区查看未结束登录工作区，确认后单独结束；普通用户只能操作自己的工作区。

L20 使用 `scnet-2` 作为共享 CPU 登录节点。dev.25 的新组件安装并认证后，`scnet-0`、`scnet-1`、`scnet-3` 可提供独占开发和按程序回执计时的批作业；环境是否可选还取决于当前授权、节点证据和接单策略。登录节点的八张卡暂不用于 GPU 作业，网页中的可分配卡数显示为 0。升级保留管理员原有的暂停和排空设置，不会为增加选项自动启用节点。

### 31.4 计时、日志、取消和结果

| 阶段 | 资源及计时 |
|---|---|
| 排队 | 不占卡，不扣卡时 |
| 分配与准备文件 | 独占节点，预留所申请的最长时长额度；准备阶段最多另留 120 秒，不计入程序用时 |
| 程序启动至结束 | 节点使用单调时钟记录启动和结束回执；秒数向上取整，计入额度的秒数不超过申请时限 |
| 清理与结果保存 | 程序运行计时已经停止；清理确认前不重新分配设备，文件保存单独显示 |
| 回执缺失或节点失联 | 显示待核对并保留预留额度，不编造结算或清理成功 |

这里的“程序开始”是固定执行器启动 Bash/Python 的边界，包含解释器和库加载时间；不是第一次 GPU kernel 的时间，也不是付费账单。卡时为整个独占节点的卡数乘结算秒数，即使程序实际只使用一张卡，仍按独占的所有卡计额度。

1. “我的作业”查看排队原因、程序用时、时限、退出码及回收状态。
2. “日志与结果”查看输出；刷新页面会恢复当前作业详情，也可收藏该作业链接。链接仍须登录且具备此作业的访问权限。当前标准输出与错误输出合并，日志有大小限制。Python 使用 `-u` 或及时 flush 可减少日志缓冲。
3. “打开文件与完整记录”进入实例文件页。保存完成后可下载结果；文件尚在保存或保存失败时按页面提示处理。
4. 排队时“取消”不会执行程序；运行时“取消”结束本作业进程。等待回收确认，不能将“已提交取消”理解为节点已经释放。
5. 到期由节点独立回收。控制面重启后只核对已有执行，不自动重跑，已完成的日志和结果仍按保留策略提供。

新批作业入口按程序回执结算；历史交互实例与旧固定任务仍沿用申请最长时长的额度规则，不能混为一种计量。管理员排空、备份和升级时，还须等待登录工作区结束、文件保存和导出完成。禁止在活动工作区上直接覆盖节点组件。

## 32. 批队列、失败和到期的完整试用

本节只提交自己创建的短任务。每个已开始的批作业独占八卡，即使脚本只做等待，也会按整节点计入额度。先确认节点属于本轮试用窗口；不取消其他用户作业来制造空闲。

### 32.1 两名用户排队

离线包另有 `examples/trial_control.py`，只用 Python 标准库，便于区分队列、程序和平台行为。

1. `trial-a` 在“我的项目”新建 `queue-trial-a`，上传 `trial_control.py`。
2. “启动项目”选入口 `trial_control.py`、参数 `--seconds 90`、批处理方式、当前可用的计算环境、时长 2 分钟；点“下一步：检查资源”，再“取消本次申请”以保存配置。
3. `trial-b` 在自己的浏览器中建立独立的同类项目，参数同样为 `--seconds 90`，完成相同配置保存步骤。
4. A 进入“批作业”，选自己的项目，名称 `queue-a`，程序最长运行秒数 `120`，提交。
5. 等 A 的“日志与结果”出现 `TRIAL_START`，B 再提交自己的 `queue-b`，同样为 `120` 秒。
6. 如果测试环境只有一台可用计算节点，B 应排队等待；如果还有空闲兼容节点，B 可以直接运行，这不属于排队故障。请在约定的独立测试资源池验证排队，不要为测试打断他人作业。记录两人的作业 ID、提交时间、状态和原因。
7. 等 A 完成并确认清理，B 才应进入运行。两人分别查看自己的日志与结果，下载 `trial-result.json`。
8. 在“我的作业”核对程序用时与结算状态，在“用量与额度”核对变化。

**通过条件：** A、B 的执行时间不重叠；B 排队期间没有程序结束回执或程序用时，不把排队墙钟时间算进程序卡时；两份结果各归其主。程序时长包含 Python 启动等开销，不要求恰好 90 秒。

例如某作业回执为 90.2 秒，按 91 秒结算，八卡用量约为 `8 × 91 ÷ 3600 = 0.2022` 卡时。确认清理前，界面可能仍保留申请最大时长对应的预留；不要把预留当作最终消耗。

若 B 因卡时余额不足被拒绝，应先调整本次时长或由管理员核对额度，这不是排队通过。将来新增了其他已认证批节点，B 可能在另一节点立即运行；那时需要专用单节点试用池才能重现本项。

### 32.2 取消排队

1. 按上一节启动 A 的等待任务。
2. B 提交后，确认还处于“排队中”，点击该行“取消”。
3. 等“已取消”，确保没有 `TRIAL_START`，且之后不再自动执行。
4. 让 A 正常完成，或按 32.4 结束自己的任务。

**通过条件：** 排队取消没有程序卡时消耗。已经进入准备或运行阶段时，不能按“未执行”作出判断，应检查启动回执和清理状态。

### 32.3 程序主动失败

1. 所有上一项资源已回收后，回到自己的测试项目。
2. 入口仍为 `trial_control.py`，参数改为 `--seconds 0 --exit-code 7`。
3. 按 31.2 的检查后取消步骤保存配置，再从“批作业”提交，程序时限 `60` 秒。
4. 查看日志、退出码、回收和结果文件。

**通过条件：** 日志有 `TRIAL_END`，退出码 `7`，任务显示失败，资源最终回收；`trial-result.json` 的 `requested_exit_code` 为 `7`。这是预期的程序失败，不应记作平台崩溃或重试成功。

### 32.4 取消运行中的任务

1. 保存参数 `--seconds 120`，以程序时限 `180` 秒提交。
2. 等日志出现 `TRIAL_START`，点击该作业“取消”。
3. 观察状态转为取消、资源进入回收，直到确认释放。
4. 核对后续日志不再持续增加；结果文件可能来不及写入，这是中断任务的正常情况。

只看到“取消请求已提交”还不算通过。节点正常时以 30 秒作为回收观察目标；超时记录 ID 和时间交管理员，不反复点击、不手动把设备标空闲。没有结束回执时，额度显示待核对，不能虚构已结算。

### 32.5 程序到期

1. 保持参数 `--seconds 120`，从“批作业”提交，程序最长运行秒数填 `20`。
2. 不手动取消，观察日志中的开始与进度。
3. 到期后程序应结束，最终资源回收，不能继续占节点。

20 秒是**程序启动后的时限**。排队不在其中；文件准备另有最多 120 秒，因此不能从点提交开始倒数 20 秒判断失效。到期时不要求有 `TRIAL_END` 或完整结果文件。

### 32.6 登录工作区的刷新、结束和到期

1. 在“登录工作区”打开自己的小项目，先填 `120` 秒，终端执行 `printf 'login trial\n' > login-note.txt`。
2. 刷新网页，找原工作区“连接 / 查看”，执行 `cat login-note.txt`。不点击“打开”重建另一个工作区。
3. 测保存时，在到期前“断开并保存到新项目”，等待保存成功，去新项目查看该文件。
4. 另开一个 60 秒工作区，写入无关紧要的小文件，等待自动到期；应不能再执行命令。检查关闭后的可读文件或保存结果。
5. 第三个工作区可测试“结束工作区”。该操作不等于“保存到新项目”，需要继续编译或提交时使用后者，或从已保存的记录显式导出。

到期记录显示“状态待核对”时，联系管理员对账；不要把它当作已释放后继续建同名实例。共享登录区每人最多一个，不随着加速卡并发额度一起扩大。

### 32.7 代码版本、文件冲突和账号边界

1. A 提交等待作业后，在项目中修改 `trial_control.py` 的提示文字并保存。已排队的作业应继续使用提交时版本；再次提交的新作业才使用新文字。
2. 两名用户分别在自己的项目中放置不同内容的同名文件。各自的项目、登录区、作业和下载记录应保持独立。
3. 同一用户两个页面同时编辑实例中的小文本，按 13.1 验证冲突提示，不应静默覆盖。
4. 只读测试账号不应能新建、提交或修改额度。未授权用户应看到明确阻塞原因，不能因知道节点名字而取得权限。

本手册不要求在生产手改 API 的他人 ID、打开他人路径、探测系统目录或直接打开设备来做攻击测试。越权接口、系统调用和设备拒绝的技术负测在专用测试环境完成；试用发现异常可见性时停止并反馈。

## 34. 管理员发布与恢复

日常版本更新可使用无需 sudo 的发布工具。首次启用仍需服务器管理员安装固定托管程序和 systemd 配置；是否已安装，可在 L20 的普通 SSH 终端执行：

```bash
python3 /usr/local/lib/infinifabric-publisher/publish_release.py status
```

只有指定的 Unix 发布操作员可以使用。网站管理员角色不等于服务器代码发布权限，普通用户也不需要访问此工具。

取得带 SHA-256 的正式交付包后：

```bash
python3 /usr/local/lib/infinifabric-publisher/publish_release.py upgrade \
  --package /path/to/verified-candidate.zip \
  --sha256 <交付记录中的完整SHA256> \
  --from-version <网站当前版本>
```

命令不加 sudo。发布程序检查无活动资源、无未知状态和待保存文件后，自动进入维护、备份、更新程序与手册、重启控制面、检查节点，再恢复发布前的维护状态。返回 `phase: complete` 后，刷新网站核对页脚版本，并打开“操作手册”和下载入口。

如果提示有活动资源，先由对应用户正常结束任务并等待资源释放、文件保存完成，不要杀服务器进程。摘要、当前版本或节点证据不符时，保留原提示交给维护人员处理。

如果新版本失败，工具保留维护状态并切回旧代码，保留当前数据库。意外中断后的恢复需要明确指定当前要保留的版本，并再次检查节点：

```bash
python3 /usr/local/lib/infinifabric-publisher/publish_release.py recover \
  --version <实际已启动的版本>
```

系统服务、Nginx、服务器账号、隔离组件或数据库格式变化仍由服务器管理员单独处理。详细机制和恢复边界见交付包中的 `docs/73-nonroot-publishing.md`。

## 35. 整机八卡训练与共享登录

使用本节示例前，请确认账号已分配资源池，所选环境支持整节点 DCU 开发。管理员可在“资源池与节点”查看节点是否允许分配。

### 35.1 两种资源策略

| 使用位置 | CPU、内存和进程 | 加速卡 | 仍保留的约束 |
|---|---|---|---|
| 独占整节点的 Bash、交互开发、批作业 | 继承云平台给该节点的上限，平台不再另加 8 GiB 数据段、32 GiB 总 RSS、128 线程等限制 | 使用整节点全部卡 | 普通 Linux 身份、私有目录、机器权限、作业截止时间、额度、取消与撤权回收 |
| 共享登录工作区 | 继承 CPU 可用范围，不固定两核；每会话 16 GiB 数据段/RSS 保护、64 GiB 地址空间、512 线程 | 禁止直接打开设备 | 每人一个工作区、节点共享容量、截止时间和文件保存策略 |

“继承节点上限”不代表超出云平台分配的物理内存、CPU 配额、进程数或存储。用户可以在整机 Bash 中用 `ulimit -a` 查看实际继承值。不要通过修改驱动、宿主参数或其他用户目录来处理应用错误。

登录区可以编辑、编译 DCU 程序，不能实际使用 DCU 计算。准备完成后保存为项目，提交到计算节点的队列。编译可从 `make -j8` 开始，再根据节点负载调整并行度；平台不会固定只给两个 CPU。

### 35.2 准备八卡示例项目

1. 下载本手册示例包，在 `examples/` 中找到 `torch_8card_transformer.py` 和 `torch_ddp_8card.py`。
2. 在“我的项目”新建项目，上传这两个文件，再新建 `run.sh`，内容见下一节。
3. 核对账号已获资源池授权，卡并发至少为 8，节点及卡时额度足够。试用时可以先申请 10 分钟，具体不超过管理员上限。
4. 选择八卡整节点环境。部分卡资源申请不能代替整节点执行认证。

两个程序使用固定种子和小型模型，不下载权重。它们用于验证模型计算、通信、检查点和结果一致性，不是大模型吞吐或容量基准。

### 35.3 整节点批作业

将以下内容保存为项目中的 `run.sh`，把批作业入口设为 `run.sh`：

```bash
#!/bin/bash
set -euo pipefail
python3 -u torch_8card_transformer.py --steps 6
python3 -u torch_8card_transformer.py --infer
torchrun --standalone --nnodes=1 --nproc_per_node=8 torch_ddp_8card.py
```

在“批作业”选择项目、计算环境和最长运行时间，提交一次。排队期间不重复提交；获配整节点、程序实际开始后才进入程序用时计量。详情中查看日志、退出码、资源回收和文件保存结果。

第一个模型的八个 Transformer 层分别放在八张卡上，训练后保存 `transformer8.pt`；后续推理读取该权重并与 CPU 结果对照。第二个程序启动八个 DDP 进程，每个进程使用一张卡并启动两个 DataLoader worker，保存 `ddp8.pt`。预期日志包含 `EIGHT_DEVICE_MODEL_OK` 和 `DDP_EIGHT_CARD_OK`，退出码为 0。

在实例文件的本次 `run-…` 目录下载 `transformer8-train-result.json`、`transformer8-inference-result.json`、`ddp8-result.json` 和检查点。DDP 结果应包含 `world_size: 8`、`loader_workers_per_rank: 2`、下降的 loss 和一致的八份权重摘要。

### 35.4 独占 Bash 中运行

1. 同一项目选择“Bash 终端”，申请一台整节点，等待资源和终端就绪。
2. 在终端执行 `pwd`、`ls`，确认已进入包含这两个 Python 文件的项目运行目录。
3. 依次执行上一节的三条计算命令。可以先运行其中一条，查看日志和结果后再继续。
4. 正常结束后下载结果，点击“停止并释放资源”，等回收确认；关闭网页不会释放节点。

八进程启动使用普通 `torchrun`，不需要 `run pytorch-check` 等平台专用命令。实际代码仍使用 PyTorch 的 `torch.cuda` 接口，DCU 的通信后端名称为 `nccl`，底层由当前环境的 RCCL 实现。

### 35.5 结果与适用范围

节点认证测试通过了八卡模型并行、八进程 DDP、每进程两个 DataLoader worker、权重保存与 CPU 对照推理；这不证明任意模型、软件版本和通信方式都已认证。当前私有通信环境用于单节点本地通信，多节点训练、外部网络和任意装包仍需另外建设。

**运行时文件可写容量与停止后的保存容量不同。** 工作目录使用临时存储。结束自动保存最多 128 MiB、256 项；实例网页传输单文件最多 128 MiB。较大的模型、数据集和检查点请使用第 36 节的个人 AFS 或共享模型目录，确认读写权限后再开始训练。

## 36. 个人 AFS 空间与共享模型

### 36.1 保存个人文件

左侧“个人存储”显示 AFS 目录、容量、最近用量和文件列表。每人默认 4 GiB，采用软配额：网页上传会检查剩余额度；Bash 直接写入暂时不能硬性限制在 4 GiB 内。超额会提示，不会自动删文件或停止程序。

1. 打开“个人存储”，确认页面列出的个人目录。没有算力申请也可管理文件。
2. 创建需要的目录，选择文件后会自动上传到当前目录。等到“文件已上传”再离开。上传只新增文件，不覆盖同名文件。
3. 下载普通文件时点击旁边的“下载”。单文件网页传输上限为 128 MiB，较大的文件请通过终端在 AFS 上操作。
4. 上传中断后重新选择同一文件，可从已确认的位置继续。需要放弃时，取消该项未完成上传。
5. 重新创建开发终端后，用以下命令确认 AFS 并保存长期结果。

```bash
echo "$IFAB_AFS_HOME"
mkdir -p "$IFAB_AFS_HOME/outputs"
printf 'hello AFS\n' > "$IFAB_AFS_HOME/outputs/hello.txt"
ls -lh "$IFAB_AFS_HOME/outputs"
```

已有账号保留原主目录，通过 `$IFAB_AFS_HOME` 访问 AFS；工作区没有同名文件或目录时，也可使用 `~/afs`。新账号的 `$HOME` 位于个人 AFS。项目仍从准备好的运行目录启动，请用 `pwd` 确认位置。

“我的项目”用于代码编辑、版本记录和任务提交，容量单独计算；原项目不会自动迁入 AFS。AFS 不随实例归档复制，结束计算或退出网页不会删除其中的文件。

### 36.2 读取共享模型

共享目录为 `/public/home/aclsylqidf/shared`，所有用户只读。读取其中权重不占个人额度。缓存和计算结果写入自己的 AFS，不向共享目录写入、删除或改名。

```bash
ls -lah /public/home/aclsylqidf/shared
ls -lh /public/home/aclsylqidf/shared/Qwen3-0.6B
```

以下代码使用现有本地模型，不下载权重。当前镜像用 eager 注意力避开缺少的 FlashAttention 动态库。

```python
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

path = "/public/home/aclsylqidf/shared/Qwen3-0.6B"
tokenizer = AutoTokenizer.from_pretrained(path, local_files_only=True)
model = AutoModelForCausalLM.from_pretrained(
    path, local_files_only=True, dtype=torch.bfloat16,
    attn_implementation="eager", low_cpu_mem_usage=False,
).to("cuda:0").eval()
inputs = tokenizer("Hello", return_tensors="pt").to("cuda:0")
with torch.inference_mode():
    output = model.generate(**inputs, max_new_tokens=16, do_sample=False)
print(tokenizer.decode(output[0], skip_special_tokens=True))
```

GPU 代码需在已授权的独占计算节点执行，CPU 登录工作区不运行 DCU 负载。其他模型需要匹配预装软件版本，目录可读不代表该模型已经通过运行认证。

2. 点击“刷新此用户用量”。未统计的用量不按零显示。
3. 修改“容量 GiB”，点击“保存容量”。这里只支持扩容；不需要重启服务，也不会增加算力权限。
4. 若提示容量已保存但节点同步未完成，等节点恢复后刷新，不要缩容或手动改 AFS 目录权限。

## 37. 上传、保存与项目大小检查

### 37.1 项目无法提交时

“下一步：检查资源”会检查整个项目，不只检查入口文件。当前环境的项目复制总上限为 128 MiB，同时限制最大单文件、文件与目录数量、目录层级。页面按本次环境显示项目实际值和上限；没有分配资源时不会按 0 张卡估算卡时。

项目库额度、个人 AFS 额度、网页单文件传输上限与任务的项目复制上限是不同限制。扩大 AFS 不会自动扩大项目复制上限。模型、数据集和大型输出应放在 AFS 或共享模型目录；代码通过绝对路径读取。整理项目文件后，重新检查资源。

### 37.2 登录工作区编辑文件

1. 在“工作区文件”填写相对路径，点击“编辑文本”读取当前文件。
2. 修改文本并点击“保存文件”。只有节点确认写入、摘要与字节数一致，而且重新读取的内容与提交一致时，才提示“已保存并核对”。
3. 文件被终端或其他页面改动时，会提示冲突并保留本页草稿。先备份草稿，再重新读取或改用另一个路径保存。
4. 切换平台菜单再返回、或重连同一个工作区，会保留本页文本。刷新或关闭标签页时，有未保存内容会提示。退出账号会清除页面缓存，重要内容应先保存或复制备份。
5. 此处保存的是本次工作区的文件，原项目不会自动更新。需要生成可提交批作业的新项目时，使用“断开并保存到新项目”。

网页编辑文本上限为 16 KiB。较大文件通过上传、下载或终端处理。下载期间请避免同时修改同一文件；检测到文件长度、版本或分块异常时，本次下载会失败，请重新下载。

### 37.3 上传较大文件

80 MiB 在网页单文件 128 MiB 的上限以内。个人 AFS、“我的项目”、登录工作区和开发实例是不同位置；上传前先确认当前页面和目标目录。

个人 AFS 上传时显示已传大小、总大小和速度。连接暂时中断会重试最多三次；仍未完成时，保留已确认位置。在同一账号、同一标签页重新选择同一文件即可续传。若刷新或换页后看不到完成提示，先检查文件列表或“未完成的上传”，不要通过更名重复上传。取消未完成上传会丢弃这一份暂存内容，不会删除原有文件。

上传完毕还会校验完整内容；看到“文件已上传”才算结束。文件过大、空间不足、同名文件和连接中断会分别提示。登录工作区、开发实例暂不提供个人 AFS 的网页续传功能；长期文件优先上传到个人 AFS，再通过 `$IFAB_AFS_HOME` 使用。

“我的项目”在数据传完后会显示后台校验进度，校验通过才加入项目文件列表。关闭页面不会取消校验；稍后重新打开项目可查看结果。等待校验不会占用计算节点或卡时，不需要通过反复更名上传来重试。

### 37.4 删除与恢复个人文件

1. 打开“个人存储”，进入目标目录，点击文件旁的“删除”。确认后移入回收站。
2. 支持普通文件、链接和空目录；不会递归删除非空目录。删除链接只处理链接本身，不删除它指向的文件。
3. 需要找回时，在回收站点击“恢复”。文件回到原位置；原位置已有同名文件时会拒绝恢复，请先移动或改名该文件。
4. 确定不再需要时，点击“彻底删除”，输入弹窗要求的完整相对路径。此操作不能恢复。
5. 回收站仍计入个人空间用量，彻底删除后才释放空间。平台不会按时间自动清空回收站。

删除前会核对文件版本。文件刚被终端或其他页面修改时，请刷新列表再操作。若提示需要核对文件状态，停止重复删除并联系管理员；平台会保留文件，不继续覆盖或递归清理。

只有有写权限的账号可删除、恢复和彻底删除自己的文件。节点未升级到支持回收站的版本时，不显示删除入口，管理员须先完成节点更新；单独更新网页不会获得删除能力。
