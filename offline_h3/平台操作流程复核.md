## 结论

目前已经证实八卡可见，但当前解释器的 H3 依赖不齐，FlashAttention 扩展实际读取被拒绝。不能仅凭这些现象断言比赛方所有环境都未准备好：还可能是未选择或未获授权使用专门的 H3 环境。

此前把当前会话当作可自行安装软件的普通 Pod、继续筹备全套离线包，是不充分的假设。应先核对 InfiniFabric 的授权环境和软件供应方式。

手册没有保证用户在 AFS 离线安装任意依赖都受支持，也不能据此断言所有用户目录安装技术上不可行。是否采用用户目录离线包，应由平台确认支持方式，不能直接照搬原始 Pod 的安装命令。

## 已有报错如何解释

- GPU 可见：进入独占计算实例的步骤已生效，但只证明设备可见。
- clang、hipcc、兼容 nvcc 在已知绝对路径可用：此前 PATH 缺项确实存在；仍不证明 xmake、构建缓存和库齐全。
- 当前 Python 找不到 diffusers、accelerate 等：当前解释器缺少依赖，不代表平台所有授权环境都缺少。
- FlashAttention 文件 stat 成功、模式 0755、os.access 返回 True，但实际 open 报 EACCES：文件仍不可用。手册描述了普通 Unix 身份之外的文件访问规则和系统调用限制；具体是哪条策略或挂载权限，需要管理员检查。不能从 ldd 的输出认定文件不是动态库，也不能先归因于 ABI。
- 手册第 36.2 节明确称当前镜像的 Qwen 示例使用 eager 注意力“避开缺少的 FlashAttention 动态库”。这是基础镜像不具备完整注意力环境的直接文档证据，但不能定位用户这个文件的具体拒绝原因。
- cpu_check.py、gpu_quickstart.py 是平台试用示例，不是 H3 依赖安装器或模型启动入口。

## 应核对的 H3 环境

POD 指南列出的验证组合如下。这是向平台核对的依据，不是建议在受管终端直接执行 pip。

```text
Python 3.11.9
厂商 PyTorch 2.9.0+das.opt1.dtk2604 / DTK 26.04
accelerate==1.14.0
diffusers==0.40.0.dev0
transformers==5.14.1
imageio==2.37.4
huggingface_hub==1.28.0
safetensors==0.8.0
regex==2026.5.9
janus==2.0.0
xxhash==4.0.2
av==18.1.0
einops==0.8.2
pytest==9.1.1
flash-attn==2.6.1+das.opt1.dtk2604.torch290
triton==3.5.1+das.opt1.dtk2604.torch290
torchvision==0.24.0（针对上述厂商 PyTorch 构建）
```

注意事项：

1. Diffusers 必须包含 `diffusers.modular_pipelines.minimax_h3`，还需提供实际验证过的源码 commit 或包校验值；开发版版本字符串不足以固定实现。用户当前 Transformers 4.57.6 与文档组合不同，不能未经验证就认定可替代。
2. torchvision 是此前清单的遗漏项。应验证 transforms 可导入、`torch.ops.torchvision.nms` 已注册；指南记录通用 wheel 与厂商 PyTorch 不兼容。
3. 海光 PyTorch 的动态注意力插件使用 `FA_SO_PATH`。InfiniCore 原生构建使用的 `FLASH_ATTN_2_CUDA_SO` 是另一项配置，不能混为一谈，也都不能解决文件读取权限问题。
4. 还需 xmake、离线构建依赖（含匹配的 Boost、pybind11）、InfiniCore/InfiniLM 原生库。启用当前 InfiniCore 的海光 FlashAttention 集成时，还会链接 `flash_attn/lib/libflash_attention.so`，仅有扩展文件名不代表完整。
5. 用户已确认 C++ ABI=True、GPU=gfx936。原生构建需对齐 ABI 与架构；当前 InfiniLM 可通过 `INFINILM_CXX11_ABI=1` 指定，海光构建应统一 `HYGON_ARCH=gfx936`。POD 指南中的 `infinicore_infer` 目标在当前 InfiniLM 构建文件中不存在，不应照抄。
6. 最终新增算子的 NineToothed、ntops 和目标后端还需匹配部署。参考环境里的 Triton/FlashAttention 不等于允许新增参赛算子绕过九齿，范围仍以要求.txt 为准。

## 正确操作顺序

1. 在“我的项目”查看可选计算环境，核对是否存在专门的 MiniMax-H3 环境及其解释器、版本、账号授权。菜单或版本不符时，以管理员确认的实际部署为准。
2. 若仅有基础 PyTorch 环境，向管理员提供上述依赖组合、当前包清单和 FlashAttention EACCES 复现，要求发布并授权可运行 H3 的环境，或明确提供独立 Pod/Slurm 入口。不要把三种环境的命令混用。
3. 源码、构建产物、日志和输出放在已授权的个人 AFS；通过 `$IFAB_AFS_HOME` 获取路径。权重读取管理员确认的共享模型目录。`/public/home/aclsylqidf/shared` 是手册中的共享根目录，但不能假设 H3 的具体子目录或权重布局已经部署。
4. “我的项目”保留小型 `run.sh` 入口和必要配置。每次脚本启动时加载平台提供的环境脚本，设置已核实的工具与库路径，再调用 AFS 中的代码。PATH 不需要靠一个始终存活的终端维持。
5. 共享登录工作区可进行平台支持的 CPU 编译准备，不可执行 DCU 负载；大型原生构建需要确认可用工具链、内存和编译时间，持久化构建目录便于分次增量编译。
6. 保存启动配置，通过“批作业”提交到授权的整节点八卡环境，在“日志与结果”查看结果。批作业不要求浏览器或终端常驻；仍有程序时限、账号额度和到期回收，不承诺可突破 30 分钟限制。耗时超上限时需管理员调整授权或提供适合的运行方式。
7. 验证顺序：包与原生扩展导入 → torchvision → POD 指南的强制 Flash SDPA 小张量运算和同步 → 官方 --legacy FL2VA 冒烟 → 当前 InfiniLM 原生路径 → 正式参数下规格、质量、性能与离线复现。

POD 指南记录了 384×576、124 帧、2 步的参考冒烟，端到端约 300 秒；展示的另一条命令是 10 步。该时间不含安装和编译，也不保证当前平台同样耗时。冒烟参数不能代替正式评测参数，--legacy 成功也不能证明原生适配完成。手册的小 Qwen eager 示例不能作为 H3 全规模注意力后端的替代方案。

## 存储限制重新解释

| 范围 | 当前依据 |
| --- | --- |
| 项目库额度 | 以页面和管理员配置为准；用户此前看到 512 MB，不能视为所有存储总量 |
| 个人 AFS | 默认 4 GiB 软配额，用户已确认可用；可由管理员扩容 |
| 项目复制到执行环境 | 手册当前上限 128 MiB，并限制项目项数和层级 |
| 实例结束自动保存 | 128 MiB、256 项，不是运行时总容量 |
| 网页单文件传输 | 最多 128 MiB；AFS 大于该值的文件需使用平台支持的终端处理方式 |
| 共享模型目录 | 只读，不占个人额度 |

因此，把完整构建树或依赖包都上传到“我的项目”仍可能失败，即使 AFS 尚有空间。AFS 不随实例归档复制。4 GiB 也不自动证明足够同时存放大型 FlashAttention、源码、安装结果和编译中间文件。
